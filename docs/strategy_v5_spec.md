# v5 仕様 — 凍結ルールの真アウトオブサンプル検証(2020〜2025) — 事前登録

作成: 2026-07-22。**本仕様は2026年以前(2025-09-30以前)のデータを一切見ずに登録する。**
v4aの改善(YTD Sharpe 1.87, DD 10.4%)にもかかわらず、2026年窓の統計検定は
boot_p=0.114 / rand_p=0.052 で4ラウンド連続ゲート未達。単一期間のデータには
約1.2σ分の証拠しか存在しないと結論し、検証データの拡張に移行する。

## 凍結ルール(= v4a、以後一切変更しない)

- ETH/USD 1h足。ttmスクイーズ(BB 20/2.0 が KC 20/1.5×ATR20 の内側、4バー以上継続)
- 解放後3バー以内に終値がBB下限を下抜け、かつ close < 日足EMA50(前日確定値) → ショート
- ロングは取らない(**ベアレジーム限定戦略**。close ≥ 日足EMA50 の期間は自動的に不参加)
- 初期ストップ 2.0×ATR14、シャンデリア・トレール 3.0×ATR14
- +1.5Rで50%利確、残玉ストップ建値へ(トレールと有利な方)
- 12バー時点で未実現R<0なら翌バー始値で手仕舞い(スケールアウト未発生時のみ)
- サイジング: 口座リスク3%/トレード、レバレッジ上限5x
- コスト: 手数料0.05% + スリッページ0.02%(片道)

## 検証プロトコル

1. データ拡張: Coinbase ETH-USD 1h/1d を 2020-01-01 まで遡って取得(15mは現状維持)
2. **検証窓(バリデーション)**: エントリー許可 2020-03-01〜2025-09-30(指標ウォームアップ後、
   かつ設計に使用した窓 2025-10-01以降と完全分離)。窓終了時に強制手仕舞い。
3. 有意性テスト(検証窓のトレードに対して):
   - bootstrap p < 0.05 (n=10000, seed=42)
   - random-entry p < 0.05 (n=1000, seed=42, 検証窓内配置)
   - 最低トレード数: 60(想定80-90。60未満なら検定力不足として不合格扱い)
4. **多重比較ガードは不要**(凍結済み単一ルール×未接触データのため)。ただし設計過程で
   2026年窓に対して約20構成を検査した事実は最終報告に明記する。
5. 補助レポート(合否に使わない): 年別成績、ベアレジーム滞在率、トレードR分布、
   2022年通年(最長ベア)の成績

## 判定後の分岐

- **合格** → エッジは実在と結論。2026 YTD成績(v4a: Sharpe 1.87 ≥ 1.5, リスク3%)を
  成果とし、事前登録済みMCスイート(optimization_mc_spec.md §2)を2026窓に適用して
  過剰最適化チェック→最終報告。追加のパラメータ最適化は原則行わない
  (要件は既に充足。プラトー確認のみ§MC4で実施)。
- **不合格** → 戦略は2026年レジームへの過剰適合と結論。設計サンプルを2020-2025に
  切替えて再設計し、2026年を純粋ホールドアウトとする方式へ移行(工程やり直し)。

## 実装

- scripts/fetch_data.py: START を 2020-01-01 に変更(1h/1dのみ。15mは 2025-10-01 起点を維持)
- scripts/run_v5.py: 凍結パラメータ固定・検証窓/2026YTD窓の両方を評価、
  有意性テストは検証窓のみ、results/v5_validation.json へ保存
- Actionsワークフロー再実行でデータ更新→ローカルへpull→実行
