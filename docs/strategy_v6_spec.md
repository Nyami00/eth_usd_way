(153トレード, Sharpe −0.11, boot_p 0.61)となり、「2026年成績はレジーム過剰適合」と確定。
事前登録済みの分岐に従い、設計サンプルを反転する。

## 原則

- **設計・最適化サンプル**: 2020-03-01〜2025-09-30(約5.6年)。ここで自由に探索してよい。
- **ホールドアウト**: 2025-11-20〜2026-07-22(ゲート窓)/2026-01-01〜(YTD窓)。
  設計中は一切評価しない。最終候補(最大3つ、事前指名・順位付け)のみを1回ずつ評価し、
  最初に基準を満たしたものを採用して終了。
- 全設計はBBスクイーズ基盤(ユーザー要件)の範囲内。

time_stop 12, コスト・3%リスク・レバ5x不変

指標キャッシュ必須。実行時間目標 < 30分。

## 候補選定基準(設計サンプル上)

1. trades ≥ 100
2. Sharpe ≥ 1.0(設計サンプル、日次×√365)
3. boot_p < 0.05 かつ rand_p < 0.05(n=10000 / n=1000, seed 42)
4. 暦年別(2020..2025)で4年以上プラス(レジーム頑健性)
5. 上記を満たす構成の中で**プラトー・スコア**(±1近傍平均Sharpe)最大の順に3構成を指名

## ホールドアウト判定(事前指名の3構成を順に1回ずつ)

- 合格 = 2026 YTD(01-01〜07-22)で Sharpe ≥ 1.5 かつ maxDD < 25% かつ トレード ≥ 10
- 最初に合格した構成を最終戦略とし、MCスイート(optimization_mc_spec.md §2の基準)を
  設計サンプルとホールドアウトの両方に適用して過剰最適化・頑健性を最終確認
- 3構成とも不合格の場合: その事実を含めて全て報告し、要件充足は不可能と結論する
  (それ自体が本リサーチの誠実な結論となる)
