# v4 仕様(トレード管理による分散削減) — 事前登録

作成: 2026-07-22。v3不合格(primary: t=1.13, boot_p=0.13, rand_p=0.058)を受けて。
狙い: 同じスクイーズ・イベント集合から R分布の分散を削り(スケールアウト・時間ストップ)、
正当なイベント追加(スクイーズ後のプルバック継続エントリー)で検定力を上げる。
ゲート閾値は変更しない(ゴールポストは動かさない)。

## v4a: トレード管理の変更(v3 primary 構造に追加)

1. **スケールアウト**: 含み益が +1.5R に到達(short: bar low ≤ entry_fill − 1.5×初期リスク距離)
   したバーで数量の50%を +1.5R 水準で利確(手数料・スリッページ適用)。
   同時に残玉のストップを建値(entry_fill)へ移動。トレーリング(3ATR)は残玉に継続適用
   (建値とトレーリングのうち有利な方=shortなら低い方を採用)。
2. **時間ストップ**: エントリーから12バー経過時点で未実現損益が 0R 未満なら翌バー始値で手仕舞い
   (スケールアウト済みの残玉には適用しない)。
3. R記録: トレードのRマルチプルは実現PnL合計/初期リスク額(分割約定を合算した1トレード扱い)。

## v4b: v4a + プルバック継続エントリー(ショートのみ)

- スクイーズ解放バーを「エピソード起点」とする。エピソードの初回トレードが手仕舞いされた後:
  - 条件: 起点から100バー以内、HTFフィルター(日足EMA50)がショート許可、
    close[t] < BBmid[t] かつ close[t-1] ≥ BBmid[t-1](ミッドラインの上から下への回帰)
  - 成立で翌バー始値ショート。サイジング・ストップ・管理(スケールアウト等)は通常と同一。
  - 1エピソードあたり再エントリーは最大2回。新しいスクイーズ解放が発生したら旧エピソードは消滅。

## ゲート(v3と同一、順次: v4a → v4b)

- 窓: 2025-11-20〜2026-07-22(1h)
- trades ≥ 30, bootstrap p < 0.05 (n=10000, seed=42), random-entry p < 0.05 (**n=5000**, seed=42;
  n増はp推定精度向上のためで閾値は不変)
- ガード: rand_p < 0.02 または 2h同構成で gate窓 Sharpe > 0.5
- 参考: YTD窓(2026-01-01〜)で Sharpe ≥ 1.5 を維持していること(成績要件)
