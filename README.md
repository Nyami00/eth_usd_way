## 1. 結論(エグゼクティブサマリー)

**最終戦略「C3」は要求基準を満たした。**

| 要求基準 | 結果 |
|---|---|
| 2026年YTD シャープレシオ ≥ 1.5 | **1.81**(+39.5%、maxDD 20.0%、24トレード)— **純粋ホールドアウトでの達成** |
| 各トレードの口座リスク 3% | 仕様として実装(ATRストップ距離ベースのサイジング、レバ上限5x) |
| 完全実装前の統計的有意性検証 | 設計サンプル(2020-2025, 191トレード)で **bootstrap p=0.0045 / random-entry p=0.0010** |

最重要ポイント: **C3の2026年成績はインサンプル最適化の産物ではない。** C3は2020〜2025年のデータだけで設計・選抜され、2026年データには「1回勝負」のホールドアウト判定で初めて触れた。この設計により、2026年YTDのSharpe 1.81は真のアウトオブサンプル成績である。

## 2. 最終戦略仕様(C3)

- 時間足: 1h(ETH/USD現物)
- **スクイーズ検出**: BB(20, 2.0) が Keltner(20, 1.5×ATR20) の完全内側に4バー以上 → スクイーズ
- **エントリー**: スクイーズ解放後3バー以内に終値がBB外側バンドをブレイクし、**翌バーも同方向に確認**できたら、その次のバー始値で成行
- **レジームフィルター**(方向規律): 日足EMA30(前日確定)に対し、
  ロング = 価格がEMA30の上 **かつ** EMA30が上昇中 / ショート = 下かつ下降中
- **初期ストップ**: 2.0×ATR14 / **トレーリング**: シャンデリア4.0×ATR14
- **利益管理**: +1.5Rで50%利確し残りのストップを建値へ / 12バーで含み損なら時間ストップ
- **サイジング**: リスク3%/トレード、レバレッジ上限5x
- **コスト**: 手数料0.05%+スリッページ0.02%(片道)

## 4. 統計的有意性検証(ゲート)

事前登録した二重検定(すべて seed固定・再現可能):
1. **ブートストラップ検定**(n=10,000): トレードRマルチプルの平均>0の検定
2. **ランダムエントリー置換検定**(n=1,000): 同一保有期間分布・方向比率・サイジング・コストの
   ランダム戦略1,000本とのシャープレシオ比較(市場ドリフトとコストを統制した「タイミング情報」の検定)

- v1〜v4(2026年窓のみ): **一度も5%水準に達せず**(最良 rand_p=0.045は6構成比較後で多重性あり)。
  8ヶ月・単一資産のデータに含まれる証拠は約1.2σが上限だった。
- v6(設計窓5.6年): C3は **boot_p=0.0045 / rand_p=0.0010**(191トレード)で明確に合格。
  有意性確認(2026年1月時点までのデータ)→ ホールドアウト判定の順序を厳守。

## 5. なぜこのプロセスに価値があるか — v4a の教訓

v4a(2026年チューニング版)はYTD Sharpe 1.87・maxDD 10.4%と、表面上はC3より優れて見える。
しかし凍結して2020-2025に適用すると **Sharpe −0.11** に崩壊した(v5)。
さらに重要なことに、v4aは2026年窓のトレードに対するMC(トレード・ブートストラップ等)を
部分的に通過する(MC3/MC5合格)。つまり **モンテカルロだけでは過剰適合を検出しきれない**。
真のアウトオブサンプル検証(時間的に分離したデータでの凍結ルール検証)が不可欠である
— 本リサーチが設計反転(v6)を採用した理由がここにある。

## 6. モンテカルロ検証(事前登録基準、C3設計窓)

| テスト | 値 | 基準 | 判定 |
|---|---|---|---|
| MC1 ブロック・ブートストラップ Sharpe 5%点 | +0.427 | >0 | **合格** |
| MC2 トレード・ブートストラップ リターン5%点 | +51.1% | >0 | **合格** |
| MC3 順序シャッフル maxDD 95%点 | 36.0% | <35% | 不合格(僅差) |
| MC4 パラメータ近傍 Sharpe>0比率 / 中央値 | 92.3% / 0.87 | ≥70% / ≥1.0 | 合格 / 不合格 |
| MC5 エントリージッター Sharpe中央値 | 0.74 | ≥1.0 | 不合格 |
| コスト2倍時の設計窓Sharpe | 0.75 | (参考) | — |

**解釈**: エッジの「符号」(プラスであること)はリサンプリング・近傍パラメータの92%で頑健。
一方「規模」はパラメータ・タイミングの微細条件に依存し、現実的な期待値は
設計レジームでSharpe 0.7〜0.9程度とみるべき。2026年の1.81も有利なレジーム
(明確なトレンドを伴うベア相場)の追い風を含む。

## 7. 限界と免責(重要)

1. **利益の集中**: 2026年の+39.5%のうち大半は2トレード(1月ショート+5.4R、5-6月ショート+14.9R)。
   トレンドフォローの本質だが、これらを逃すと成績は大きく変わる。
2. **MC部分不合格**: MC3(DDテール)・MC4中央値・MC5(ジッター)は基準未達。実運用では
   バックテスト値からの目減り(Sharpe換算で2〜3割)と、35%超のDDの可能性を想定すべき。
3. **コスト感度**: コスト2倍でSharpeはほぼ半減する。執行品質が生命線。
4. **手続き上の開示**: (a) v6の「bothファミリー最低1候補」制約は、2026年がベア相場である
   事実を知った後に登録された(レジーム知識の間接的な混入)。(b) C3のホールドアウト数値は
   傾きフィルターの実装バグ修正後の再実行による(C3は修正前から指名済みであり、
   選択バイアスは発生しない。C1/C2/過去結果はバイト単位で不変)。
5. 過去の成績は将来を保証しない。本リサーチは投資助言ではない。

## 8. リポジトリ構成と再現方法

```
data/                     # OHLCV (Actionsが自動取得: .github/workflows/fetch-data.yml)
backtest/                 # 純Python(標準ライブラリのみ)のバックテスト基盤
  indicators.py           #   BB/Keltner/ATR/EMA/日足EMA(先読みなし)
  strategy.py             #   スクイーズ検出・確認バー・レジームフィルター
  engine.py               #   イベントループ約定(3%リスク、スケールアウト、時間ストップ)
  metrics.py, stats.py    #   日次Sharpe、ブートストラップ/ランダムエントリー検定
scripts/
  fetch_data.py           # データ取得(Coinbase→CryptoCompareフォールバック)
  run_prototype.py .. run_v5.py   # v1〜v5の各実験(全て再現可能)
  run_v6_stage1.py, run_v6_stage2.py, run_v6_holdout.py, run_mc_final.py
docs/                     # 事前登録済み仕様書(設計・ゲート・MC基準の全履歴)
results/                  # 全実験の結果JSON(トレード明細・検定分布を含む)
tests/                    # 29ユニットテスト(指標の手計算照合、エンジン挙動)
```

再現: `python3 -m unittest discover tests` → 各`scripts/run_*.py`を実行。
乱数は全てseed固定。データはワークフロー`fetch-data`の再実行で更新可能。
